# Ring Fighter — How the code works

All game code lives in `Assets/Scripts` (namespace `RingFighter`). Editor-only tools live in `Assets/Editor`.

## The big picture

```
Ring Rig (RingRig)
 ├─ Main Camera (TrackedNode: Head)
 ├─ Left Hand  (TrackedNode: LeftHand)  └─ Aim (pointing direction)
 └─ Right Hand (TrackedNode: RightHand) └─ Aim

Ring Controller (RingController + RingEnergy + one component per move)
 ├─ LaserMove
 ├─ ChargedBlastMove
 ├─ WhirlwindMove
 └─ ShieldMove

Training Dummy (TrainingDummy, implements IDamageable)
Energy Bar (EnergyBarVisual, floats above the left hand)
```

The scene is generated by **Ring Fighter > Build Training Scene** (`Assets/Editor/RingFighterSceneBuilder.cs`).
Rebuilding replaces `Assets/Scenes/TrainingArena.unity`, so tuning values changed only in the scene are lost on
rebuild. Change defaults in the scripts (or in the builder) to make them stick.

## Scripts

| File | Job |
| --- | --- |
| `TrackedNode.cs` | Reads one XR device (head or controller): pose, trigger/grip/buttons, velocity, a short position history for gestures, and haptics. Updates again just before rendering to avoid lag. |
| `RingRig.cs` | Holds head and hands; sets floor-level tracking; logs an error if VR isn't running. |
| `RingEnergy.cs` | The energy meter: `TrySpend`, `Drain`, regeneration. |
| `Move.cs` | Base class for every move, plus `RingContext` (what a move can access). |
| `RingController.cs` | Runs all moves each frame, tracks which hands are busy, decides which move starts. |
| `Gestures.cs` | Pure gesture math: `IsCircling`, `IsGuarding`, `HandsTogetherAtSide`. Most "feel" tuning lives here and in move fields. |
| `LaserMove.cs`, `ChargedBlastMove.cs`, `ShieldMove.cs`, `WhirlwindMove.cs` | The four moves. |
| `Projectile.cs` | Flying energy ball; sphere-casts each frame so fast shots can't pass through targets. |
| `IDamageable.cs` | Interface for anything that can be hit. |
| `TrainingDummy.cs` | Practice target: wanders, flinches, health bar, falls, respawns. |
| `EnergyBarVisual.cs` | The floating energy bar. |
| `Impact.cs` | Hit feedback made in code: expanding burst, floating damage number, generated thump sound. Called by `TrainingDummy.TakeDamage`. |
| `Fx.cs` | Helper to make collider-less placeholder shapes. |
| `AimAssist.cs` | Targets register an aim point; shots within a few degrees are redirected onto the nearest live target. |
| `MoveLog.cs` | Short list of recent move events (fired / skipped and why) for the debug readout. |
| `DebugReadout.cs` | Floating panel (front-left) showing per-hand trigger, speed, pose, circling angle, active moves, and the move log. Created by `RingController` when *Show Debug Readout* is ticked; Y on the left controller toggles it. |

## How a move is chosen each frame

1. `RingController` calls `Observe()` on every move (moves use this to watch button presses).
2. It calls `Tick()` on moves that are already running; a move calls `Finish()` when done.
3. For each hand that is free, it asks moves in **priority order** (highest first) to `TryStart`.
   A move that starts claims its hand(s) via `UsedHands` (1 = left, 2 = right, 3 = both).

Priorities (set in the scene builder): Charged blast 30, Whirlwind 20, Shield 10, Laser 0.

A trigger pull on the Laser Move is decided once: release within `holdDelay` (0.22 s) fires a single bolt; still
held after that starts the laser. Neither happens if the pull is clearly for another move: the
controller isn't pointing forward (blocking pose), the hand is swinging (whirlwind), or the hands are together
(blast). Every skip is logged with its reason. While it runs it claims the hand, and it cuts out if the hand
swings hard so a whirlwind can take over.

Aim direction: `TrackedNode.AimForward` is the controller's forward tilted down by `aimPitchOffset`, because the
raw controller axis points up the handle. The value is tuned in the headset (debug panel: A more, B less) and
saved in PlayerPrefs under `RF_AimPitch`. All pose checks (laser, shield) use this same direction.

## Tuning workflow

1. Play with the debug readout visible. Do a move and watch the readout: pose label (AIMING / BLOCKING),
   `fwd` value, speed, and circle angle, plus the "Recent" log saying what fired or why it was skipped.
2. Adjust the matching field on the move component (each has a tooltip), or tell Claude the numbers you saw.
3. Defaults in scripts only apply to a freshly built scene: after changing defaults, run
   **Ring Fighter > Build Training Scene** again.

## Adding a new move

1. Create `Assets/Scripts/MyNewMove.cs` with a class extending `Move`.
2. In `TryStart(int freeHands)`, check the gesture (add helpers to `Gestures.cs` if needed). For a lasting move,
   set `IsActive = true` and `UsedHands`, return true. For an instant move, do the effect and return true.
3. If it lasts, implement `Tick()` and call `Finish()` when it ends. Clean up visuals in `OnFinish()`.
4. Add it to the Ring Controller in `RingFighterSceneBuilder.cs` (with a priority and materials), then rebuild the scene.
5. Document it in `docs/GAME_DESIGN.md`.

## Conventions

- Tuning values are public fields with tooltips, so they're adjustable in the Inspector.
- Visual effects are built from primitives via `Fx.Shape` until real art arrives.
- Unity files are committed as text (Force Text) with `.meta` files. Never commit `Library/`, `Temp/`, `Logs/`, `Builds/`.
