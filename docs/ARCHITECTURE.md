# Ring Fighter — How the code works

All game code lives in `Assets/Scripts` (namespace `RingFighter`). Editor-only tools live in `Assets/Editor`.

## The big picture

```
Ring Rig (RingRig)
 ├─ Main Camera (TrackedNode: Head)
 ├─ Left Hand  (TrackedNode: LeftHand)  └─ Aim (pointing direction)
 └─ Right Hand (TrackedNode: RightHand) └─ Aim

Ring Controller (RingController + RingEnergy + one component per move)
 ├─ LaserMove
 ├─ ChargedBlastMove
 ├─ WhirlwindMove
 └─ ShieldMove

Ring Controller also has PlayerHealth (hit spheres follow the headset)
Player HUD (PlayerHud: curved health bar left, energy bar right, red flash/fade)
Training Dummy (TrainingDummy, implements IDamageable; charges and fires EnemyBolt)
```

Command-line builds: `Assets/Editor/CommandLineBuild.cs` (`BuildQuest`), driven by `tools/build-quest.ps1`.

The scene is generated by **Ring Fighter > Build Training Scene** (`Assets/Editor/RingFighterSceneBuilder.cs`).
Rebuilding replaces `Assets/Scenes/TrainingArena.unity`, so tuning values changed only in the scene are lost on
rebuild. Change defaults in the scripts (or in the builder) to make them stick.

## Scripts

| File | Job |
| --- | --- |
| `TrackedNode.cs` | Reads one XR device (head or controller): pose, trigger/grip/buttons, velocity, a short position history for gestures, and haptics. Updates again just before rendering to avoid lag. |
| `RingRig.cs` | Holds head and hands; sets floor-level tracking; logs an error if VR isn't running. |
| `RingEnergy.cs` | The energy meter: `TrySpend`, `Drain`, regeneration. |
| `Move.cs` | Base class for every move, plus `RingContext` (what a move can access). |
| `RingController.cs` | Runs all moves each frame, tracks which hands are busy, decides which move starts. |
| `Gestures.cs` | Pure gesture math: `IsCircling`, `IsGuarding`, `HandsTogetherAtSide`. Most "feel" tuning lives here and in move fields. |
| `LaserMove.cs`, `ChargedBlastMove.cs`, `ShieldMove.cs`, `WhirlwindMove.cs` | The four moves. |
| `Projectile.cs` | Flying energy ball; sphere-casts each frame so fast shots can't pass through targets. |
| `IDamageable.cs` | Interface for anything that can be hit. |
| `TrainingDummy.cs` | Practice target: wanders, flinches, health bar, falls, respawns. |
| `EnergyBarVisual.cs` | The old floating energy bar over a hand. Not used by the scene any more (the HUD replaced it). |
| `PlayerHealth.cs` | Player health, head and torso hit spheres, hit flash, knock-out and fight restart. `PlayerHealth.Instance`. |
| `EnemyBolt.cs` | The dummy's yellow bolt (also: clashes with your projectiles via `ClashWith`, laser cuts via `CutAlong`): hits the player, is absorbed by a single shield (`ShieldMove.AbsorbHit`) or reflected by a double shield (`ShieldMove.Intercept` is the plane-crossing test). |
| `PlayerMovement.cs` | Off-hand thumbstick movement: Dash (default), Smooth, Off; click the stick to cycle. Moves the rig (player root), clamped to an arena circle. Independent of the move system. |
| `PauseControl.cs` | Left menu button toggles pause (`Time.timeScale` 0, floating "PAUSED" sign). `PauseControl.IsPaused` stops ring moves in `RingController`. |
| `PlayerHud.cs` | Builds the curved health/energy bars as meshes, soft-follows the head, draws the red flash and death fade. |
| `HitShapes.cs` | Physics-free hit detection: targets register an upright capsule; `Segment` (shots, laser) and `Overlap` (whirlwind) test against them. Used alongside physics so hits work even if colliders are missing. |
| `Impact.cs` | Hit feedback made in code: expanding burst, floating damage number, generated thump sound. Called by `TrainingDummy.TakeDamage`. |
| `Fx.cs` | Helper to make collider-less placeholder shapes. |
| `AimAssist.cs` | Targets register an aim point; shots within a few degrees are redirected onto the nearest live target. |
| `MoveLog.cs` | Short list of recent move events (fired / skipped and why) for the debug readout. |
| `DebugReadout.cs` | (A/B aim tuning is ignored while paused so it can't clash with the pause menu's A/B.) Floating panel (front-left) showing per-hand trigger, speed, pose, circling angle, active moves, and the move log. Created by `RingController` when *Show Debug Readout* is ticked; Y on the left controller toggles it. |

## Visual effects (VFX)

Effects are drawn by separate components that **read** the moves' state; they never change gameplay. Code lives in
`Assets/Scripts/VFX`; shaders, materials and textures live in `Assets/VFX` (`Shaders/`, `Materials/`, `Textures/`;
the shaders are procedural, so `Textures/` is empty for now). Look: white-hot core inside a green halo (lightsaber),
faked with additive shaders and a few layered shells. Real bloom is an optional toggle.

```
VFX System (scene object, made by RingFighterSceneBuilder)
 ├─ VfxLibrary   template materials (Assets/VFX/Materials), one per shader; the scene references them
 └─ VfxSystem    attaches LaserVfx / BlastChargeVfx / ShieldVfx / WhirlwindVfx to the moves, owns pooled
                 BurstFx objects, switches bloom, adds VfxPauseMenu
```

| File (`Assets/Scripts/VFX`) | Job |
| --- | --- |
| `VfxLibrary.cs`, `VfxMaterials.cs` | The library holds the template materials; `VfxMaterials` clones them at runtime (shared glow materials are cached, animated ones are per owner). No `Resources` or `Shader.Find`: the shaders stay in the Quest build because a scene object references them. |
| `VfxSystem.cs` | Boots the effects, bloom volume (URP Bloom, camera post-processing flag). If the library is missing it does nothing and the old placeholder shapes show. |
| `VfxSettings.cs` | Quality (High / Low / Minimal) and bloom, saved in PlayerPrefs (`RF_VfxQuality`, `RF_VfxBloom`). |
| `VfxPauseMenu.cs` | The panel under the PAUSED sign: A = quality, B = bloom. |
| `ProjectileVfx.cs` | Added to every `Projectile`: bolt streak or blast sun-orb, comet tail, embers, and the blast explosion when it ends (told by `Projectile.NotifyEnd`). |
| `EnemyBoltVfx.cs` | Added to every `EnemyBolt`: yellow / orange (`HeadShot`) / green (`IsReflected`) with flicker and embers. |
| `LaserVfx.cs`, `BlastChargeVfx.cs`, `ShieldVfx.cs`, `WhirlwindVfx.cs` | Read their move's placeholder shapes (`BeamPlaceholder`, `OrbPlaceholder`, `DiscTransform`, `RootTransform`, `InContact`, ...), hide them and draw the effect. |
| `BurstFx.cs` | Pooled one-shot hit effects: Impact (flash, ring, sparks) and Explosion (adds shell and ground ring). Called from `Impact.cs`. |
| `VfxParticles.cs`, `VfxMeshes.cs` | Small particle-system builder (world space, one shared additive material, Emit bursts) and the funnel mesh. |

Shaders (`Assets/VFX/Shaders`): `RF_Glow` (fresnel glow shell with tail fade, pulse, shimmer), `RF_Particle` (soft
dot / spark streak), `RF_RingDisc` (rings, spiral-arm ground circle), `RF_Funnel` (wind streaks), `RF_Shield`
(hex grid, rim, ripple). All unlit, additive, no textures or keywords, with single-pass-instanced stereo macros and
`UnityPerMaterial` constant buffers (SRP Batcher compatible).

Small read-only hooks added to existing scripts (no logic changes): `LaserMove.BeamPlaceholder/TipPlaceholder`,
`ChargedBlastMove.OrbPlaceholder/Charge01`, `ShieldMove.DiscTransform/ImpactCount/LastImpactPoint`,
`WhirlwindMove.RootTransform/Discs/InContact`, `EnemyBolt.IsReflected/HeadShot`, `Projectile.isBlast` (set by the
charged blast), and `Impact.SpawnBurst` calls `BurstFx` first.

**Adding or changing an effect:** put the shader in `Assets/VFX/Shaders`, add a material for it in
`RingFighterSceneBuilder.GetVfxMaterial`, add a field for it to `VfxLibrary`, assign it in the builder's "VFX System"
block, then clone it through `VfxMaterials`. Include `.meta` files for new assets. If a shader is only loaded by
name, the Quest build can strip it.

## How a move is chosen each frame

1. `RingController` calls `Observe()` on every move (moves use this to watch button presses).
2. It calls `Tick()` on moves that are already running; a move calls `Finish()` when done.
3. For each hand that is free, it asks moves in **priority order** (highest first) to `TryStart`.
   A move that starts claims its hand(s) via `UsedHands` (1 = left, 2 = right, 3 = both).

Priorities (set in the scene builder): Charged blast 30, Whirlwind 20, Shield 10, Laser 0.

**Ring hand / off hand.** `RingContext.RingHand` is null until the player picks it (RingController shows a prompt
and runs no moves until a trigger is pulled); `RingContext.OffHand` is the other one. Moves that attack read only
`RingHand`. The Laser Move: ring hand alone = each pull fires an instant bolt; with the off hand within
`focusDistance` (focus stance) a pull waits `holdDelay`: release = bolt, still held = laser, which claims BOTH
hands (`UsedHands = 3`) and stops if the hands drift past `focusBreakDistance`. Shield: either hand starts it; in
`Tick` the other hand joining the pose merges it into a double shield (`IsDoubled`, `Strength`); `UsedHands`
changes as arms join or drop. Skips are logged with reasons.

Aim direction: `TrackedNode.AimForward` is the controller's forward tilted down by `aimPitchOffset`, because the
raw controller axis points up the handle. The value is tuned in the headset (debug panel: A more, B less) and
saved in PlayerPrefs under `RF_AimPitch`. All pose checks (laser, shield) use this same direction.

## Tuning workflow

1. Play with the debug readout visible. Do a move and watch the readout: pose label (AIMING / BLOCKING),
   `fwd` value, speed, and circle angle, plus the "Recent" log saying what fired or why it was skipped.
2. Adjust the matching field on the move component (each has a tooltip), or tell Claude the numbers you saw.
3. Defaults in scripts only apply to a freshly built scene: after changing defaults, run
   **Ring Fighter > Build Training Scene** again.

## Adding a new move

1. Create `Assets/Scripts/MyNewMove.cs` with a class extending `Move`.
2. In `TryStart(int freeHands)`, check the gesture (add helpers to `Gestures.cs` if needed). For a lasting move,
   set `IsActive = true` and `UsedHands`, return true. For an instant move, do the effect and return true.
3. If it lasts, implement `Tick()` and call `Finish()` when it ends. Clean up visuals in `OnFinish()`.
4. Add it to the Ring Controller in `RingFighterSceneBuilder.cs` (with a priority and materials), then rebuild the scene.
5. Document it in `docs/GAME_DESIGN.md`.

## Conventions

- Tuning values are public fields with tooltips, so they're adjustable in the Inspector.
- Visual effects are built from primitives via `Fx.Shape` plus the effect shaders (see "Visual effects" above), until real art arrives.
- Unity files are committed as text (Force Text) with `.meta` files. Never commit `Library/`, `Temp/`, `Logs/`, `Builds/`.
